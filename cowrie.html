INTRUSION DETECTION · ACADEMIC PROJECT

SSH Brute Force Detection
Using Cowrie Honeypot.

A controlled cybersecurity lab designed to simulate SSH brute-force activity and examine how a Cowrie honeypot captures, records and presents intrusion attempts for analysis.

Cowrie Ncrack Kali Linux Python Flask VirtualBox

01 / OVERVIEW

Project Overview.

This project explored honeypot-based intrusion detection by deploying Cowrie as a simulated SSH service and using Ncrack to generate controlled brute-force authentication attempts.

The environment was designed to demonstrate the complete detection process — from attack simulation and event capture to JSON log analysis and visualisation through a web-based monitoring dashboard.

PROJECT TYPE Academic Group Project
AREA Intrusion Detection
DEFENSIVE TOOL Cowrie Honeypot
ATTACK TOOL Ncrack

02 / CONTRIBUTION

My Contribution.

As a member of the project team, I contributed across the full project lifecycle, including lab environment setup, network configuration, Cowrie deployment and configuration, Ncrack attack simulation, log monitoring and analysis, Flask dashboard implementation, testing, documentation and presentation preparation.

03 / ENVIRONMENT

Lab Environment.

The project was implemented using two Kali Linux virtual machines in Oracle VirtualBox.

ATTACKER VM

Kali Linux + Ncrack

Generated controlled SSH brute-force authentication attempts against the honeypot.

IDS VM

Kali Linux + Cowrie

Operated as the honeypot and captured incoming SSH connections and authentication activity.

A Host-Only Adapter provided isolated communication between both virtual machines, while NAT provided controlled internet connectivity. Cowrie listened for SSH connections on TCP port 2222.

ARCHITECTURE DIAGRAM

Attacker VM → Ncrack → SSH :2222 → Cowrie → JSON Logs → Flask Dashboard

04 / IMPLEMENTATION

Honeypot Deployment.

Cowrie was deployed inside a Python virtual environment on the IDS machine. Its configuration was prepared and the honeypot service was initialised using the Twisted framework.

Once operational, Cowrie reported that it was ready to accept SSH connections, and the service was verified as listening on TCP port 2222.

EVIDENCE 01

Cowrie service running and ready to accept SSH connections on port 2222.

05 / SIMULATION

Attack Simulation & Detection.

A controlled SSH brute-force attack was performed from the attacker VM using Ncrack against the Cowrie honeypot.

The simulation used the username root with the Rockyou password wordlist. The attack was deliberately throttled by limiting active connections and using a low timing template.

EVIDENCE 02

Controlled SSH brute-force simulation performed from the attacker VM using Ncrack.

Cowrie successfully captured the incoming SSH activity and recorded information including source IP addresses, timestamps, session information and event details.

EVIDENCE 03

Cowrie JSON logs showing captured SSH activity from the attacker machine.

06 / ANALYSIS

Log Analysis & Monitoring.

Cowrie generated structured JSON logs containing security-relevant information that could be used to analyse the captured SSH activity.

src_ip dst_ip timestamp session duration eventid

These records made it possible to examine where connections originated, when activity occurred, the type of event detected and the lifecycle of individual sessions.

Monitoring Dashboard

Rather than relying only on raw terminal output, the project also used a Flask-based dashboard to present Cowrie activity through a web interface.

The dashboard displayed information including attack time, attacker IP address, attempted username and password, and session status.

EVIDENCE 04

Flask monitoring dashboard displaying captured Cowrie authentication activity.

07 / OUTCOME

Project Outcome.

The project successfully demonstrated a complete controlled intrusion-detection workflow. Cowrie detected and recorded the simulated SSH activity, while its structured logs provided information that could be analysed to understand connection and authentication behaviour.

SIMULATE → CAPTURE → LOG → ANALYSE → VISUALISE

The Flask dashboard provided a more accessible way to monitor captured events and translate raw honeypot logs into readable security information.

08 / TAKEAWAYS

Key Takeaways.

Through this project, I gained practical experience in deploying and configuring a honeypot, creating an isolated virtual attack environment, simulating authentication attacks, analysing structured security logs and presenting captured security events through a monitoring interface.
